How HTTP Works

HTTP stands for Hypertext Transfer Protocol. It is a communication protocol used by web browsers and servers to exchange information. When someone opens a website, the browser sends a request and the server sends a response. This process allows users to access web pages, images, videos and other online resources (MDN Web Docs, n.d.).

How a Browser Requests a Web Page

Opening a website involves several steps that happen very quickly. The browser and the web server communicate to find and display the requested page.

  1. 1. Entering the URL

    The user enters a URL into the browser's address bar. A URL identifies the resource the user wants to access, including the protocol and the domain name.

  2. 2. DNS Lookup

    The browser needs to find the IP address connected to the domain name. It uses the Domain Name System (DNS), which translates domain names into IP addresses. This helps the browser locate the correct server.

  3. 3. Connecting to the Server

    After finding the IP address, the browser establishes a connection with the server. For HTTP/1.1 and HTTP/2, this normally involves a TCP connection. For HTTPS, a TLS handshake is also used to establish a secure connection.

  4. 4. Sending an HTTP Request

    The browser sends an HTTP request to ask for the required resource. The request contains a method, such as GET, and headers that provide additional information. GET is commonly used to request a web page, while POST is often used to send information from a form.

  5. 5. Receiving an HTTP Response

    The server processes the request and sends an HTTP response. The response includes a status code, headers and, in many cases, a body containing the requested HTML document. A status code such as 200 means that the request was successful.

  6. 6. Loading Additional Resources

    The browser reads the HTML document and discovers other resources needed by the page. It sends additional requests for files such as CSS stylesheets, images and JavaScript. When these resources arrive, the browser uses them to display the complete page.

These steps usually happen in a fraction of a second. HTTP uses a request-and-response model, which means that the client starts communication by sending a request and the server answers it (Fielding et al., 2022).

HTTP Request and HTTP Response

HTTP Request

An HTTP request is a message sent by the browser to a web server. It contains a request method, a resource address and headers. Some requests, such as POST, can also include a body with information sent to the server.

Common request methods include GET, POST, PUT and DELETE. GET retrieves information, POST sends information, PUT updates or creates a resource, and DELETE requests the removal of a resource.

HTTP Response

An HTTP response is the message returned by the server. It contains a status code that describes the result of the request, response headers with additional information and sometimes a body with the requested content. The browser uses this response to decide how to display the resource (Fielding et al., 2022).

HTTP vs. HTTPS

HTTPS stands for Hypertext Transfer Protocol Secure. It is the secure version of HTTP and uses Transport Layer Security (TLS) to protect communication between a browser and a server. TLS encrypts the information being exchanged, helping prevent other people from reading it while it travels across the network.

HTTPS also helps protect the integrity of information and verifies the identity of the website through digital certificates. A certificate helps the browser check that it is communicating with the intended website. This is especially important when users log in, enter personal information or make online payments (MDN Web Docs, n.d.).

Without HTTPS, information sent over an unencrypted connection could be intercepted or changed by attackers. This is why modern websites should use HTTPS to protect their visitors.

Common HTTP Status Codes

HTTP status codes are three-digit numbers returned by a server. They tell the browser what happened when it processed a request. Status codes are divided into five groups, depending on their first digit (Internet Assigned Numbers Authority, n.d.).

Examples of common HTTP status codes
Status Code Name Meaning
200 OK The request was successful.
301 Moved Permanently The resource has a new permanent URL.
403 Forbidden The server understood the request but refuses access.
404 Not Found The requested resource could not be found.
500 Internal Server Error The server encountered an unexpected problem.

HTTP Versions and the Future

HTTP has developed over time to improve communication between browsers and servers. HTTP/1.1 introduced persistent connections, while HTTP/2 added features such as multiplexing and header compression. HTTP/3 uses QUIC to improve how data is transported across the network (Fielding et al., 2022).

There is no official HTTP/4 standard. HTTP/3 is the latest major version described in the current HTTP standards. Future improvements may be introduced, but HTTP/4 is not currently an established version.
